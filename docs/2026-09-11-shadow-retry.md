# 2026-09-11 修复：收盘自动流水线跑太早 → 拿不到当日日线（改为"校验+重试，成功才写 marker"）

> 按「每次大改动在 docs/ 下留说明」约定。已合入 main。

## 现象

09-11（周五）收盘后，服务 15:45 的自动流水线"跑成功了"，但**当天的数据其实没进来**：

```
[26] 完成：成功 559/559，新增 0 行 → large_pool.db 559 只，最新 2026-09-10
[27] live40    打分完成 599 只，日期 2023-11-16 ~ 2026-09-10     ← 没有 09-11
[28] 累积：OOS 日子 3（其中已有收益 0）                          ← 停在 3 天
```

于是 OOS 天数没推进（09-11 缺失），而**兜底定时（16:25）也没救回来**：
worker 在流水线跑完后**无条件写了 `logs/shadow_ab_date`**，兜底定时一看"今天已跑过"就跳过了补跑。

## 根因

**行情源的「当日日线」在收盘后一段时间才发布**。实测同一天：

| 时刻 | `scripts/26` 结果 |
|---|---|
| 15:46（服务自动） | 成功 559/559，**新增 0 行**（源尚未发布当日线） |
| 16:55（手动复跑） | 成功 559/559，**新增 558 行** → 最新 2026-09-11 |

即 15:45 这个触发点**早于大池路径拿到当日日线的时间**。
（注：同一天 15:30 的 40 池刷新 `market.db` 却拿到了 09-11——两条路径的源/实现不同，不能互相推断。）

## 修复

`api/main.py`

1. 新增 `_shadow_data_current(day)`：读 `data/large_pool.db` 的 `MAX(date)` 判断是否已推进到当天。
2. `_shadow_ab_worker` 改为**「跑 → 校验 → 没推进就等一会重试」**：
   - 每次跑完流水线后校验；未推进则间隔 `retry_interval_min`（默认 10 分钟）重试；
   - 到 `retry_until`（默认 18:30）仍未推进 → 报错并 **不写 marker**（留给兜底定时补跑）；
   - **只有校验通过才写 `logs/shadow_ab_date`**。

`config/config.yaml`（`auto_refresh.shadow_ab`）新增：

```yaml
retry_interval_min: 10   # 未拿到当日日线时的重试间隔（分钟）
retry_until: '18:30'     # 重试截止；到点仍未拿到则本日不写 marker，留给兜底定时
```

设计取舍：保留 15:45 的**早触发**（有些日子源发布得快，就能早拿数据），
用重试兜住"发布晚"的日子 —— 比单纯把时间推到 17:00 更稳，也不牺牲早完成。

## 当日补救

手动补跑 `26`（16:55，+558 行）→ `27`（09-11 已入库）→ `28`：
OOS 累积 **3 → 4 天**（09-08 ~ 09-11），仍 0 个可评日（前向收益需 5 个交易日后才产生）。

## 验证

- `py_compile` OK；`_shadow_data_current` 实测：今天 → True、明天 → False、昨天 → True。
- 修复后服务已重启（17:03）。
