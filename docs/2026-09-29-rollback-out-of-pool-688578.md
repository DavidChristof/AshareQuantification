# 回退池外持仓 688578 + 从此不买池外股票

**日期**：2026-09-29
**起因**：用户看「模拟炒股」页，问「资产构成」与「持仓盈亏分布」两块**怎么还有 688578 这只股**。
**结论**：688578 是**真持仓**（不是幽灵）—— 但池外持仓这件事本身是设计上的坑，用户决定
**当作从没买过地回退掉**，并且**此后不再买池外股票**；顺带修掉展示层那个名字回退 bug。

---

## 1. 先确认真实性：它确实是真持仓，不是重复计/幽灵

用户的第一反应是「还有 bug」。所以先把它证伪/证实清楚：

- 按 `paper_trades` **全量重放**（43 笔），现金重建 = `42291.50097771723`，
  与库中 `42291.50097771723` **分毫不差**；6 只持仓股数全对。
- 688578 的 100 股只来自 **id=37 一笔**（2026-09-24 买入），**无任何卖出记录**。
- 它的价格也是对的：接口给的 `106.25` 正是 `data/large_pool.db` 里 2026-09-29 的收盘价。
- 账户页与净值曲线当时已经**对得上**（都是 `96648.50` = `42291.5 + 54357`），
  说明 09-24 的取价修复（`_held_valuation_prices`）已生效。

⇒ **出现在那两块图里本身是对的。** 用户感觉别扭的其实是另一件事（见第 6 节的名字 bug）。

## 2. 决策与做法

**决策**：当作从没买过 —— 删掉那笔买入流水、按流水重建，并把历史净值点重新对齐流水。
理由：池外持仓让「成交路径（有池外兜底）与估值路径（只认 40 池）不对称」这个坑反复冒头，
取价路径虽已修好，但池外持仓仍是持续噪声源（展示层名字、止盈止损拿不到实时价……）。
**与其每次给池外补漏，不如不买。**

## 3. 回退的算术

现金退回该笔买入的 `amount`（已含费用）`11303.859782892598`：

| 日点 | cash | mv | equity |
|---|---|---|---|
| 2026-09-24 | 52720.84 → **64024.70** | 43990.00 → **33568.00** | 96710.84 → **97592.70** |
| 2026-09-28 | 54517.51 → **65821.37** | 41935.00 → **31336.00** | 96452.51 → **97157.37** |
| 2026-09-29 | 42291.50 → **53595.36** | 54357.00 → **43732.00** | 96648.50 → **97327.36** |

mv 的减少量正好是 688578 那 3 天的市值：`10422.00 / 10599.00 / 10625.00`
（= 100 × 当日收盘 104.22 / 105.99 / 106.25）。

> 注意 `2026-09-24` 回退后的 mv `33568.00` **正是 09-24 事故里那个"错误值"** ——
> 因为那就是"不含 688578"的持仓集合。同一个数，这次是**对的**（因为持仓里真的没有它了）。

## 4. 净值点：改写 3 行、删除 11 行、保留 1 行

**改写（重算）3 行** —— 见上表。日点**只依赖当天收盘时可知的信息**（该日为止的现金 +
该日收盘价），所以按同一口径重算是**不引入未来信息**的，可以精确重建。

**删除 11 行**（不可重建的盘中点）：

```
2026-09-28 09:00 / 10:00 / 11:00 / 13:00 / 14:00
2026-09-29 09:00 / 10:00 / 11:00 / 13:00 / 14:00 / 15:00
```

盘中点写的是**实时价**，而实时快照不留存（`data/minute.db` 里 688578 有 0 行）
=> 拿收盘价去补等于**注入未来信息**，比删掉更糟。沿用 09-24 那次的处理
（`docs/2026-09-24-manual-equity-missing-position.md` §7）。
顺带：09-28/09-29 的 `15:00` 行本来就是各自日点的副本。

**保留 `2026-09-24 09:00`** —— 它是**成交前**写的，不属于受影响范围。
证据（脚本每次都自己断言，不靠人记）：

```
该点 cash = 54198.301125691825  ==  09-23 收盘的 PIT 现金（完全相等）
09-23 持仓 = {002558, 002709, 600549, 601138, 603993}  <- 没有 688578
```

判据也不硬编码 key：规则是「**09:00 早于 09:30 开盘，所以只有买入当天的 09:00 点可能
写在成交之前**」，其余每天的 09:00 反映的是**含该持仓**的前收盘状态，照样删。

**行数 112 → 101。**

## 5. 代码改动

### 5.1 `PaperBroker` 拿到「更正与修复」三件套（上移，不是复制）

`trade_history_with_id` / `delete_trade` / `rebuild_from_trades` 原本只长在 `RealBroker` 上，
但它们是**纯流水代数**（只读写 `paper_trades`/`paper_account`/`paper_positions`，不含任何
实盘专有状态）。**2026-09-29 上移到基类 `PaperBroker`，并从 `RealBroker` 删除** ——
手动盘此前**没有**删除+重建的能力（前端那句「按流水全量重建资金/持仓」只对实盘成立）。

安全性：只有 `RealBroker` 继承 `PaperBroker`，两者都没重写 `_connect`；`max_price` 的保留
逻辑是表驱动的；`BEGIN` 在新建连接的空事务里执行。`tests/test_real_account.py` 靠继承
照常通过，并**新增**了一条用**普通 `PaperBroker`** 的测试把这个上移钉住。

### 5.2 两个新工具

- `rebuild_daily_points(close_of, dates=None)` —— 日点按「该日为止的现金 + 该日收盘市值」
  重算。`close_of` 由调用方注入（`paper.py` 不依赖行情库）。**任一持仓当日无价 -> 该点
  整点不写**（记入 `missing`），绝不拿别的价格凑 —— 与 `snapshot_equity` 的「缺价不写」同口径。
- `drop_equity_points(keys)` —— 按 key 精确删除（专清不可重建的盘中点）。

放基类而不是塞进一次性脚本：`PaperBroker` 本来就拥有 `paper_equity`（`snapshot_equity` 写、
`equity_history` 读、`reset` 清），而且 `scripts/42` 的审计显示日点漂移**会复发**（见 §8），
这是个长期有用的修复工具；更关键的是 `tests/` 里**没有任何文件 import `api/main.py`**，
放进 broker 才能被测试覆盖。

### 5.3 `scripts/46_rollback_poolout_holding.py`

`--apply` 才真写，默认**在库的副本上真跑一遍**再丢掉副本 —— 预演显示的就是会得到的结果。
`close_of` 复用 `scripts/42::make_close_of`（40池→559池→全市场），不复制那份阶梯
（跨脚本 import 的写法照 `scripts/45` 的 `_s18()`）。

## 6. 顺带修掉的展示 bug：池外名字回退成裸代码

`/api/manual/positions` 用的是 `_name()` —— 它只查 40 池的 `STOCK_NAMES`，查不到
`return symbol`。于是 688578 被渲染成裸代码：

- 「资产构成」饼图上 `688578: 11.0%`
- 「持仓盈亏分布」y 轴上 `688578 688578`（前端就是 `p.name + ' ' + p.symbol`，名字回退后写了两遍）
- 「我的持仓」名称列 `688578`

本文件其余 **8 处**早就用对了 `_display_name()`（它会去最近选股候选里找真名，专为池外设计），
**只漏了 `manual_positions` 这一处**。改成 `_display_name(pos.symbol)`。
（真名其实一直在手上：`results/daily_selection.json` 里 `688578 -> 艾力斯`。）
加了闸门后池外持仓为 0、此 bug 已不可达，但留着就是隐患，故仍修。

## 7. 闸门：不再买池外股票

买入路径只有三条：

| 路径 | 处理 |
|---|---|
| `/api/manual/order`（单笔下单） | **本来就有闸门**：`if order.symbol not in DATA: 404` |
| `/api/portfolio/apply`（一键组合调仓） | 无 -> 经下面同一个咽喉 |
| `_auto_open_execute_worker`（09:31 自动开盘） | 无 -> 同上 |

后两条都经 `_portfolio_with_reasons()`，其 `trade = [r for r in _selection_rows() ...]`
是**唯一咽喉**（`/api/portfolio` 展示接口也走它 ⇒ **展示与成交天然一致**）。
改为调用新的纯函数：

```python
tradable_candidates(rows, universe, allow_out_of_pool=False)   # quant/data/selector.py
```

开关：`config.trading.allow_out_of_pool: false`（**缺省即禁**）。

**为什么抽成 selector 里的纯函数**：`tests/` 里没有任何文件 import `api/main.py`
（引它就会加载模型、起后台线程），内联过滤等于**没有回归**。

**副作用（已实测）**：目标集不含池外 ⇒ `portfolio_apply` 第 1 步会把任何池外持仓按
`组合调仓·掉出topN` **自动卖掉** —— 这条路径从此**自清洁**。回退后池外持仓为 0，所以
下次调仓是空操作。
**残余边界**（记录在案）：第 1 步要求 `p.symbol in prices`，而 `_build_prices` 只对**当前
选股候选**里的池外票给价；若某池外持仓已掉出候选列表，它会**卖不掉**。回退后无此情形。
