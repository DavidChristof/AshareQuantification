# 事故收尾：buy() 并发透支、实盘日点口径、止盈止损搬出读接口、恒等式护栏

**日期**：2026-09-17
**起因**：2026-09-17 两个账本事故（重复卖出、日点按前一天价格写）的遗留项，用户要求一次做完
**结论**：四项全部完成。**恒等式护栏第一次运行就抓到了新东西**（自动纸面盘 7 个日点，根因待查）。

## 1. `buy()` 的 TOCTOU —— 并发买入可透支现金

与「重复卖出」**完全同一类**：

```python
cash = self.query_cash()                       # 事务外读
if total_cost > cash + 1e-6: return ...        # 事务外校验
with self._connect() as conn:
    conn.execute("BEGIN")                      # BEGIN 在读之后
    conn.execute("UPDATE paper_account SET value = value - ? ...")
```

两个并发买入都能读到**同一笔现金**、都判「资金足够」⇒ 透支。
改成 `BEGIN IMMEDIATE` 后再读、再判、再扣（与 `sell()` 同一手法）。

**测试有牙**（还原旧代码后跑）：

```
AssertionError: 4000 元只够买一次(≈3001 元)，却成交了 6 次 —— 并发买入透支了现金
```

## 2. `_sync_real_equity()` —— 守卫恒真 + 价格来源不对

它与手动盘有**完全相同**的两处问题：

1. 守卫 `str(hist[-1]["date"]) >= latest` 恒为真（`'D 15:00' > 'D'`）；
2. 日点用 `_real_prices()`（**实时价**）配 `latest`（**交易日**）当键 —— 日期与价格不同天。

**只修 ① 会更糟**：它会**开始往曲线里写错值**（原来因为守卫恒真，反而什么都没写）。
所以必须连价格来源一起改：

- 新增 `_close_on_date(symbols, date)`：按 `market.db` → `large_pool.db` → `full_market.db`
  依次查**那一天真正的收盘价**；
- 拿不到某个持仓的当日收盘价 ⇒ **宁可不写**，绝不拿别的价格凑（并记一条 warning）。

## 3. 止盈止损从**读接口**搬进后台线程

原来它挂在 `/api/manual/account` 与 `/api/manual/positions` 上 —— **读接口里下单**。
看板一轮询就触发，**触发频率是秒级**，把 `sell()` 的竞态放大成了必然。

新增 `_manual_stop_worker`（守护线程）：

- 每 30 秒一次（`manual.stop_check_interval_sec`），**只在交易时段**；
- 不再依赖「有没有人开着看板」；
- `manual.auto_stops: false` 可整体关掉。

`_apply_manual_stops` 自身也加了交易时段闸（`force=True` 可绕过，测试用）——
**盘前不再拿昨收价下单**（2026-09-17 那笔正是 09:23 盘前成交的）。

## 4. 恒等式护栏

新增 `quant/trading/audit.py` + `scripts/42_audit_accounts.py`：

| 恒等式 | 能抓住 |
|---|---|
| 现金 `== 初始 - Σ买入 + Σ(卖出-费用)` | 重复卖出、并发透支、漏记/多记成交 |
| 日点 `equity == cash + Σ持仓×当日收盘` | 日点按别的日期价格写、持仓/现金与净值不同步 |
| 当日收益 `== Σ浮动 + Σ今日卖出(相对昨收) + Σ今日买入浮动 - Σ当日费用` | 基线算错、成交漏记 |

**为什么必须做**：这两个事故**全程零异常、零告警** —— 账本算错了程序不会抛异常，
只能靠恒等式去对。`tests/test_audit.py` 8 条，每条都配「**clean 必须过 / broken 必须报**」一对。

用法：

```bash
.venv/Scripts/python.exe scripts/42_audit_accounts.py       # 三个账户
.venv/Scripts/python.exe scripts/42_audit_accounts.py --quiet   # 只在有问题时输出
# 退出码 1 = 有恒等式不成立，可挂到定时任务上告警
```

## 6. 护栏第一次跑就抓到了东西（**未定性，未改动**）

```
[paper]  cash=-0.00（对得上） | 日点 7 个不符 | *** 有问题 ***
[manual] 通过      [real] 通过
```

自动纸面盘 7 个日点的 `market_value` 与「持仓 × 当日收盘」对不上（09-04 ~ 09-15）。

**已验证：不是**「D-1 定价」那个 bug —— 我逐日比对了「当日价」与「前一天价」两种算法：

| date | stored_mv | 按当日收盘 | 按前一天收盘 |
|---|---|---|---|
| 2026-09-11 | 99661.58 | 97986.93 | 101036.08 |
| 2026-09-14 | 97620.89 | 97686.05 | 97754.85 |

**两个都不吻合**，所以不是同一个病。

**根因未查明，本次未做任何改动。** 已知的相关线索：该账户在 2026-09-09 做过一次
**手工数据修复**（删过一笔坏成交 + 一个坏持仓 300750），这会让**该日期之前的持仓
无法从流水完整重建**，因此这 7 条里可能有一部分是那次修复的**残留痕迹**而非新 bug。
（我核对过该账户**当前**持仓与流水完全一致，所以不是重建方法本身失效。）

⇒ **要单独排查**。护栏的价值恰恰在这里：它把「数字对不上」变成了**可重复的检查**，
而不是等人某天偶然看出来。

## 7. 教训

1. **同一个 bug 会长在同一个代码库的多个地方。** `sell()` 的 TOCTOU 修完，
   `buy()` 里躺着一模一样的写法；手动盘的守卫 bug 修完，`_sync_real_equity` 里
   一字不差地重复了一遍。**修完一个并发/事务 bug，必须全库搜同类写法。**
2. **「修一半」比不修更危险。** `_sync_real_equity` 如果只修守卫、不修价格来源，
   会从「什么都没写（因为守卫恒真）」变成「开始写错值」。**改一处逻辑前，先问
   「另一半是什么在兜着它」。**
3. **读接口绝不能有副作用。** 这次不是「顺手写坏了」，是**架构上**把下单放进了轮询路径，
   于是触发频率从「每天几次」变成「每秒几次」，任何竞态都被放大成必然。
4. **有构造副作用的 API，调用前必须确认目标存在。** 我用错配置键，就把 4 张表
   建进了行情库 —— 因为 `PaperBroker(path)` 对不存在的路径是**创建**而不是报错。
