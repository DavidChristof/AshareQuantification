# 趋势闸门：为什么是沪深300？—— 以及口径修好之后，闸门的「效果」就没了

**日期**：2026-09-16
**起因**：用户问「大盘趋势闸门为什么用沪深300而不是上证指数？」
**结论**：**没有理由**（继承来的，不是选出来的）；更关键的是——
把回测口径对齐到实盘可执行之后，**当初验证出的那个「改善」消失了**。
闸门在 3 个指数 × 2 个宇宙的 6 组配对检验里，**没有一组显著**。

复现：`.venv/Scripts/python.exe scripts/37_risk_rerun_pit.py --index sh000300|sh000001|sh000905`

---

## 1. 先回答「为什么是沪深300」：查无理由

翻了三个地方：

| 出处 | 关于指数选择的全部内容 |
|---|---|
| `config.yaml:283` | `index: sh000300  # 大盘代理（与 _market_weakness 同源，新浪指数接口）` |
| 引入提交 `6e700b4` | 通篇讲回测结果（7.4%/Sharpe 0.57 vs 熔断 0.9%/0.15），**指数一个字没有**，只有「真实沪深300 实证」 |
| `docs/2026-09-11-risk-control.md` | 同上，只有「用真实沪深300（新浪日线）：...」 |

也就是说：**当初拿沪深300做的验证，然后就把验证用的那个指数直接配成了线上口径。**
中间**没有做过沪深300 vs 上证的比较**。config 里那句「与 `_market_weakness` 同源」
是事后找的相似性，而且**这句话本身是错的**（见下）。

### 顺带查出的两个真问题

**（1）`market_trend_gate.index` 这个配置项是假的。** 只有 `api/main.py:2237` 会读它，
下面三处**硬编码 `sh000300`**：

```
quant/data/selector.py:322           <- 选股的市场状态判定
scripts/37_risk_rerun_pit.py:187     <- 闸门回测（本次已修）
scripts/40_pit_select_backtest.py:152
```

⇒ 改 config 会让**线上闸门变、回测和选股不变** —— 正是 2026-09-14 修掉的那类
「回测口径 ≠ 线上口径」。**`scripts/37` 本次已修；另外两处仍未修。**

**（2）`_market_weakness` 根本不是「同源」。** 它读的是沪深300 **和** 上证**两个、取更差的那个**：

```python
for i in IndexQuoter().fetch():
    if i.get("code") in ("sh000300", "sh000001"):
        idx_pct = min(idx_pct, p) if idx_pct is not None else p
```

弱势降仓 = 「两个指数里谁跌得狠听谁」；闸门 = 「只听沪深300」。行为不同，注释是错的。

---

## 2. 两个指数实际差多少（先说量化）

2020-01-02 ~ 2026-09-15，1626 个交易日：

| | 沪深300 | 上证指数 |
|---|---|---|
| 日收益相关系数 | **0.9592** | |
| 阻断率（昨收 < 昨日MA20） | **51.1%** | 46.2% |
| 阻断日未来5日（各自指数口径） | +0.16% | +0.25% |
| 放行日未来5日 | -0.03% | -0.02% |
| 不重叠窗口 t | +0.79 | +0.92 |

```
结论不一致的日子 = 195 天 (12.0%)
    其中「300 拦、上证放」= 137 天
        「上证拦、300 放」=  58 天
```

**12% 的日子结论不同，而且严重不对称**——分歧里 70% 是沪深300 更严。
所以换指数**不是换个名字，是把闸门松紧调一档**（51% → 46%）。

顺带：**两个指数都不支持闸门有效**——阻断日的未来收益都**比放行日更好**（t 均不显著），
与 `docs/2026-09-14-trend-gate-semantics.md` 的指数级结论一致。

---

## 3. 第二层修复：把 `scripts/37` 的口径对齐到「实盘可执行」

原实现有两处**实盘无法落地**的口径错误（09-14 文档点出的第二层）：

| | 原实现 | 问题 | 改成 |
|---|---|---|---|
| `ma_ok` | `idx >= idx.rolling(20).mean()` | **今收 vs 今日 MA20**，但闸门 09:31 执行，**不知道当日收盘** | `c.shift(1) >= ma20.shift(1)`（昨收 vs 昨日 MA20） |
| `ir`（弱势判断） | `idx.pct_change()` | 用**当日收盘涨跌幅**，同样是未来函数。线上 `_market_weakness()` 读的是**实时**涨跌幅 | `open(D) / close(D-1) - 1`（今开/昨收，≈09:31 的实时涨跌） |

改后两者都只用 **D-1 及之前**，与 09:31 实盘可执行的信息集一致。

**对齐的正确性已核对**：新旧 `ma_ok` 的结论差异率 = **13.0%**，
与 09-14 文档记录的 **12.9%** 吻合（微小差异来自多了几天 + 腾讯源 2 位小数取整）。

同时加了 `--index`（默认 `sh000300`，保持原行为），输出改为
`results/risk_rerun_pit_<index>.json`（三次跑不互相覆盖）。

## 4. 关键结果：口径一修，闸门的「改善」就蒸发了

### 4.1 修之前（有未来函数）—— PIT 无偏宇宙

```
A 基准 -59.8%      B +熔断 -31.4%      C +闸门 -14.7%      D -6.0%
                    熔断 -0.36         -0.20               -0.07
                                     ↑ 闸门「改善」+16.7pp
```

### 4.2 修之后（可执行口径）—— 同一个 PIT 宇宙

| 大盘代理 | A 基准 | B +熔断 | C +闸门 | D +弱势 |
|---|---|---|---|---|
| sh000300 沪深300 | -59.8% (0.36) | -31.4% (-0.36) | **-32.9% (-0.73)** | -34.9% (-0.64) |
| sh000001 上证 | -59.8% | -31.4% (-0.36) | -23.6% (-0.57) | -23.6% (-0.57) |
| sh000905 中证500 | -59.8% | -31.4% (-0.36) | -21.8% (-0.55) | -21.2% (-0.54) |

**用当前配置的沪深300：闸门让结果变差（-31.4% → -32.9%），Sharpe 从 -0.36 掉到 -0.73。**

⇒ **当初那个 +16.7pp 的「改善」，是未来函数偷看的。**
这正好印证 09-14 文档写过的话：「回测验证的是一个**无法落地**的信号」。

### 4.3 配对检验（同一批调仓期，只差一个开关）

n = 239 个调仓期。逐期收益之差做单样本 t：

| 宇宙 | 大盘代理 | 闸门 C−B 逐期均差 | **t** |
|---|---|---|---|
| pit | sh000300 | -0.037%/期 | **-0.23** |
| pit | sh000001 | +0.014%/期 | **+0.09** |
| pit | sh000905 | +0.023%/期 | **+0.15** |
| large | sh000300 | -0.096%/期 | **-0.51** |
| large | sh000001 | -0.059%/期 | **-0.32** |
| large | sh000905 | -0.055%/期 | **-0.30** |

**6 组全部不显著，而且符号随宇宙/指数翻转。**
（弱势减半 D−C 同样全部不显著，t 在 -0.87 ~ +1.14。）

### 4.4 为什么「总收益差 10pp」没有意义

以 pit/sh000300 为例：逐期均差 -0.037%、t = -0.23
⇒ 均值的标准误 = 0.037/0.23 = **0.161%/期**
⇒ 累积 239 期的不确定度 ≈ 0.161% × 239 ≈ **±38pp**

各组的累积不确定度都在 **±37 ~ ±45pp**。
**所以总收益上 10~25pp 的差异，连一个标准误都不到。**
这也解释了为什么 3 个日收益相关 0.96 的指数，能把同一条闸门给出 11pp 的差距
（pit 的 C：-32.9 / -23.6 / -21.8）。

## 5. 结论与建议

### 5.1 指数那个问题：**是个伪问题**

在闸门本身的效果都测不出来的前提下，纠结用哪个指数，是**在优化一个二阶量**。
而且换指数带来的差异（11pp）**远大于**闸门本身的可测效果（≈0，t≈0.1）。

### 5.2 我的建议：**关掉闸门，而不是换指数**

```yaml
market_trend_gate:
  enabled: false
```

理由：
1. 它**唯一**的实证支持（7.4%/Sharpe 0.57）是在**有幸存者偏差的池子**上、
   用**未来函数**测出来的。本次口径对齐后，在无偏宇宙上收益反而不如不加。
2. 配对检验 6/6 不显著。
3. 指数级证据也不支持（阻断日未来收益不更差，t≈0.8）。
4. PIT 重跑（09-11）本来就没能复现它的改善，本次是第三次独立证据。

**这是你的系统，改配置会影响模拟盘/实盘的建议输出，所以我把结论摆出来、由你定。**
你要改我就改；想再观察也行。

### 5.3 如果想保留一个闸门

**先别挑指数**。要做的话，路径是：
1. 把 `selector.py:322` 与 `scripts/40:152` 的硬编码也改成配置驱动（否则 config 仍是假的）；
2. 先扩大样本或换一个**有区分度**的风险代理（现在 MA20 是 50% 命中率的硬币）；
3. 明确「什么叫有效」——本次用的是逐期配对 t，下次沿用同一把尺子。

### 5.4 本次证据的局限（必须一起看）

- **PIT 基准策略本身巨亏**（-59.8% / 年化 -16.9%）。在一个大幅亏损的策略上做风控叠加，
  统计功效很低，「风控」这个框架本身就是退化的。**这削弱了本节所有结论的强度。**
- n=239 期，4.5 年，单一市场状态。
- `large` 池有幸存者偏差，绝对值不可信；但它作为**第二个独立样本**给出了矛盾结论。
- 「没有证据表明有效」**不等于**「证明了无效」—— 只能说：**现有证据不支持保留它**。

## 7. 教训

1. **一个参数「一直这么写的」，不等于它被论证过。** 沪深300 出现在配置里，
   只是因为当初拿它做的验证 —— 而**验证用的东西很容易顺手变成线上口径**。
2. **未来函数会把「无效」装扮成「有效」，而且装扮得很像。** 同一个宇宙、同一套组合，
   只把信号挪后一天：-14.7% 变 -32.9%，Sharpe -0.20 变 -0.73。
   **一个 12.9% 的日子结论相反的信号，就足以制造出 16.7pp 的假改善。**
3. **总收益是最没信息量的比较方式。** 这里的总收益标准误是 ±40pp，
   而大家习惯盯着 10pp 的差距下结论。**配对检验（同期、只差一个开关）才是对的尺子。**
4. **换一个 0.96 相关的指数就能让结论翻符号** ⇒ 说明测量的是噪声。
   **这种「同信号不同代理」的自检，应该成为风险类结论的常规动作。**
