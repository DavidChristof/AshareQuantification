# `scripts/28` 的结论永远打不出来 —— GBK 控制台吞掉输出

**日期**：2026-09-15
**起因**：跑例行兜底 `26→27→28`，`28_shadow_check.py` 崩在 `UnicodeEncodeError`
**结论**：本机控制台是 **GBK**，而 `28` 用 `✓`/`✗` 打印判定表，这两个字符不在 GBK 里。
更糟的是——**这张表挡在 `STABLE`/`NOT_YET` 判定之前**，所以崩在这里 = 结论永远不输出。

---

## 1. 事故本身

```
[28] 累积：OOS 日子 6（其中已有收益 1）
[28] 前向 OOS（> 2026-09-07，1 天）：
      live40     平均RankIC=0.0204  ICIR=0.000
      shadow600  平均RankIC=0.0325  ICIR=0.000
Traceback (most recent call last):
  File "scripts/28_shadow_check.py", line 91, in main
    print(f"      [{('✓' if v else '✗')}] {k}", flush=True)
UnicodeEncodeError: 'gbk' codec can't encode character '✗'
```

**为什么以前没暴露**：这段检查表只有走到「有 OOS 可评日子」才会执行。
此前前向 OOS 一直是 0 天，`28` 在更早的分支就 `return` 了，**根本没走到这里**。
2026-09-15 首次攒够 1 个可评日 → 首次走到检查表 → 首次崩。

**后果**：兜底定时任务（以及任何调用 `28` 的地方）**看不到 `STABLE`/`NOT_YET`**。
讽刺的是，这个 bug 恰好把「该不该上线 600 池」的判定给屏蔽了——**最需要它说话的时候它闭嘴**。

**修法**：`✓/✗` → `OK/--`（纯 ASCII）。中文本身在 GBK 里，不需要动。

---

## 2. 这是系统性问题，不止一个文件

全仓扫描（**含 `tests/`**，只扫 `scripts/quant/api` 会漏）：

```
135 个 .py，33 个命中，13 种字符，共 200 处
```

| 字符 | 码位 | 处数 | 换成 |
|---|---|---|---|
| `¥` | U+00A5 | 87 | `￥`（U+FFE5，**在 GBK 内且视觉等价**） |
| `⇒` | U+21D2 | 33 | `=>` |
| `️` | U+FE0F | 30 | 删（变体选择符） |
| `⚠` | U+26A0 | 28 | `[!]` |
| `−` | U+2212 | 16 | `-`（ASCII 连字符） |
| `²` | U+00B2 | 7 | `^2` |
| `⏸` | U+23F8 | 4 | `[暂停]`（仅 scripts/tests） |
| `✓` `✗` | U+2713 U+2717 | 3 | `OK` / `X` |
| `🟢` `🛑` `⇓` `↔` | U+1F7E2 U+1F6D1 U+21E9 U+2194 | 4 | `[开]` `[停]` `v` `<->` |

⚠️ 一开始我按「**只改会被 print 的字符串**」来估，得出 25 个文件 —— 那是**错的**：
「这个字符串会不会被打印」在 Python 里**无法可靠判定**（返回值可能被调用方打印、
日志调用散布各处）。28 这个 bug 恰恰就是这种推理的假阴性。所以改成按文件类型一刀切。

## 3. 分两档处理（为什么不是全仓一刀切）

关键在于：**api/main.py 里的 🟢⏸🛑⇓ 不是控制台输出，是给浏览器渲染的 UI 文案**
（JSON 的 `text` 字段，看板上直接显示）。把它们换成 `[开]`/`[暂停]` 只会**把看板变难看**，
却换不来任何安全收益 —— 它们根本不走 GBK 控制台。按「一刀切」改等于**用真实的 UI 损失
换一个不存在的风险**。

所以按「这段字符串究竟落在哪」分档：

| 范围 | 处理 | 理由 |
|---|---|---|
| `scripts/` `tests/` | **整文件清干净**（含注释/docstring，零豁免） | 它们**就是控制台程序**，`print` 直接落 GBK 控制台 |
| `quant/` | 清掉**无损可替**的那几类（`¥`/`⇒`/`−`/`²`/`⚠`/`↔`） | 库；它的字符串会被脚本 `print` 出去 |
| `api/main.py` | 只做无损替换，**保留 4 个 UI 符号** | UI 文案，不是控制台输出 |

结果：**32 个文件、201 处**替换；`¥`→`￥` 做得**完全无损**（U+FFE5 在 GBK 内，
长得一模一样，零信息损失）。

对 `api/main.py` 保留的那 4 个符号，补**运行时兜底**（不是修复）：

```python
for _stream in (sys.stdout, sys.stderr):
    try:
        _stream.reconfigure(errors="replace")
    except (AttributeError, ValueError):
        pass
```

即：万一它们经 logger/异常路径落到 GBK 控制台，退化成 `?` 而不是崩。
中文在 GBK 内不受影响。

## 4. 测试护栏

新增 `tests/test_gbk_output.py`（4 条）：

1. `test_all_python_files_are_gbk_encodable` —— 除显式豁免外，**所有 .py 必须能 GBK 编码**。
   这条**无假阴性**，因为它不需要判断「字符串会不会被打印」—— 那正是 28 漏掉的地方。
2. `test_scripts_and_tests_are_strictly_clean` —— 控制台程序**一个豁免都没有**。
3. `test_exempt_list_is_deliberate` —— 豁免名单里已清干净的文件必须移出，
   防「豁免名单变成只增不减的垃圾抽屉」。
4. `test_the_crash_that_motivated_this_is_fixed` —— 直接锁住 28 的判定表不得再用那两个码位。

**写着写着就被自己抓了两次**：这条测试第一次运行时报的 offender 就是
`tests/test_gbk_output.py` 自己 —— 先是我在 docstring 里写了 `⇒`，改掉后又是写了 🟢。
这也顺带证明了这条测试有效。**所以本文件只在注释里写码位，不写那些符号本身。**

## 6. 教训

1. **「平时没报错」不等于「没问题」**：这条 `print` 一直在代码里，只是从没被执行到。
2. **结论性输出必须用最保守的字符集**。日志/判定表是给机器和定时任务读的，
   它们的编码环境往往比交互终端更差 —— **别用 checkmark/warning/箭头这些"好看"的符号**
   （码位 U+2713 U+2717 U+26A0 U+21D2）。
3. **不要用 `PYTHONIOENCODING=utf-8` 掩盖问题**：它让当前会话舒服了，
   却让真实控制台下的崩溃推迟到某个更关键的时刻才爆。
4. **别按「这个字符串会不会被打印」来估风险** —— 那件事在 Python 里无法可靠判定，
   我按那条路子估出的「25 个文件」就是错的（实际 33 个）。**按文件类型一刀切才可靠**：
   控制台程序整文件清干净，其余只做无损替换。
5. **但「一刀切」也不能无脑铺到 UI 文案上**：api 的 🟢⏸🛑 换成 `[开]` 是**真实的 UI 损失**，
   换不来任何安全收益（它们不走控制台）。**先问「这段字符串落在哪」，再决定怎么治。**
6. **护栏测试最大的价值是它会先抓到自己**：新测试第一次跑就报 `test_gbk_output.py` 自己
   （我先在 docstring 里写了那两个符号）。**能被自己触发的测试才是真在测东西。**
