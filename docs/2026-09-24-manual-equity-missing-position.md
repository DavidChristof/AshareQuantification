# 手动盘净值漏算一整笔持仓 —— 40 池外的票「买得进、估不出」

**日期**：2026-09-24
**起因**：用户报「今天买了 688578 但未计入账户净值曲线」。
**结论**：不是数据缺失、也不是模型问题 —— 是**手动盘的净值快照漏了一级取价兜底**。
688578（科创板）**不在 40 池信号表里**，日点的价格源当时只有 40 池 ⇒ 取不到价 ⇒
`snapshot_equity` 把它**静默按 0 计**并照常写点。
**已修**：手动盘日点改用 `_close_on_date`（三个库按交易日取收盘价）+「缺价不写」，
盘中点改用覆盖池外的 `_build_prices`，`snapshot_equity` 补上点名告警；
历史数据已修正（下详）。

---

## 1. 事故的算术（可复现）

09-24 手动盘成交 4 笔（`组合调仓`）：买 688578 100 股 @ 113.0047、买 000792 400 股、
卖 002709 300 股、卖 600549 200 股。收盘持仓 5 只。

| | cash | market_value | equity | 当日 |
|---|---|---|---|---|
| 库里 09-24 日点（事故） | 52720.84 | **33568.00** | **86288.84** | **-12.27%** |
| 用当日收盘重算（正确） | 52720.84 | **43990.00** | **96710.84** | **-1.68%** |

**证明它「不是别的错、就是漏了那一笔」**：把 688578 剔掉后，

```
601138 100 x 61.00 + 603993 500 x 17.08 + 002558 400 x 23.62 + 000792 400 x 23.70
= 6100 + 8540 + 9448 + 9480 = 33568.00
```

与库里存的 **33568.00 一分不差**。差额 `100 x 104.22 = 10422.00` 正好是 688578 的市值。
⇒ 曲线上凭空多出一根 **-12.27%** 的假暴跌。

## 2. 根因：**成交路径与估值路径不对称**

| 路径 | 价格函数 | 有没有「池外」兜底 |
|---|---|---|
| **成交**（`portfolio_apply`） | `_build_prices` | **有** —— 实时 -> SIGNALS -> **选股候选 price（覆盖池外）** |
| **估值**（`_sync_manual_equity` 日点） | 原来直接遍历 `SIGNALS` | **没有** —— `SIGNALS` 只有 **40 池** |
| 估值（盘中点） | `_live_prices` | **没有** —— 实时 + SIGNALS，同样只有 40 池 |

=> **买得进（成交能定价）、估不出（估值不能）**。

而孪生函数 `_sync_real_equity` 在 **2026-09-17 那次净值事故**里**已经改对了**
（见 `docs/2026-09-17-equity-date-mismatch.md`）：

```python
closes = _close_on_date(held, latest)          # 三个库依次查当日收盘
missing = [s for s in held if s not in closes]
if missing:
    logger.warning("[real] 缺 %s 在 %s 的收盘价，本次不写日点", missing, latest); return
```

**那次补丁只打给了实盘，手动盘漏了** —— 于是「实盘口径正确、手动盘口径错误」。
这和第 3 节那个放大器一起，构成了这次事故。

## 3. 放大器：`snapshot_equity` **静默**跳过无价持仓

`quant/trading/paper.py`（修正前）：

```python
for pos in self.query_positions():
    price = latest_prices.get(pos.symbol)
    if _valid_price(price):            # 取不到价 -> 直接跳过 -> 什么都不记
        market_value += pos.shares * price
# 照样 INSERT OR REPLACE 写点
```

**没有告警、没有回退、照样落库。** 与之对照，`live_summary`（账户接口那条路）**会**回退
`pos.avg_cost` —— 所以同一时刻：

- `/api/manual/account` 给 **97589.31**（688578 按成本 113.005）
- 曲线上是 **86288.84**（688578 按 0）
- 真实是 **96710.84**（688578 按收盘 104.22）

**三个数、都不对。** 这正是用户看到的「买了但没进曲线」：账户页看着还行，曲线是断的。

## 4. 影响范围：只此一天、只此一只（已审计）

逐日重建了手动盘的持仓，再把**每一只交易过的票**对一遍 40 池：

```
688578  40池=False  559池=True   全市场=True     <- 唯一一只出过 40 池的
其余 13 只  40池=True
```

- **688578 是手动盘历史上唯一一只 40 池外的票**（14 只交易过的票里）；
- **09-24 是唯一持仓含池外票的一天**（09-03 ~ 09-23 逐日审计 `漏算=[]`）；
- **自动纸面盘**（8 只持仓全在 40 池）与**实盘**（0 持仓，且 `_real_quotes` 本就覆盖池外）
  **都未受影响**。

## 5. [!] 这不是一次性意外 —— 池外持仓是**设计内的常态**

组合调仓的目标来自 `_portfolio_with_reasons()`，即**每日选股候选**（面比 40 池宽得多）；
40 池只是「常驻行情 + 常驻信号表」的那 40 只。**677 只候选里的任何一只都可能被选进持仓** ——
过去只是恰好还没选到 40 池外的票，所以这个洞一直没露出来。**它必然会再犯**，
所以修的是取价路径，不是补 688578 这一个特例。

## 6. 修复

| # | 文件 | 改动 |
|---|---|---|
| 1 | `api/main.py::_sync_manual_equity` | **日点**改用 `_close_on_date(held, latest)`（三个库按交易日取收盘价）；缺一个就**不写日点**（与实盘同口径）。不再用 `SIGNALS` |
| 2 | 同上 | **盘中点**价格源从 `_live_prices()` 换成 `_build_prices(held)`（含「选股候选 price」池外兜底）；仍缺价就**不写盘中点** |
| 3 | `quant/trading/paper.py::snapshot_equity` | 无有效价的持仓**必须 `logger.warning` 点名**（symbol 列表 + 库路径），不再静默 |

第 2 条还有个附带好处：盘中估值与**成交价同源**（`portfolio_apply` 也走 `_build_prices`），
账户自己的数之间不再打架。

## 10. 遗留（如实记下）

1. **手动盘盘中点用的是近似价**：池外票走 `_build_prices` 的「选股候选 price」兜底，
   那是**选股那一刻**的价（非实时）。比按 0 计好得多，但**不是真日内价**。
   想要真价可以改用 `_real_prices`（它经 `_real_quotes` **对池外做批量抓取**，
   见 `_real_quotes` 的 docstring）——本轮**没动**，因为那会给被秒级轮询的读接口
   加网络依赖，且手动盘的成交价本来就来自 `_build_prices`（同源优先）。
2. **`snapshot_equity` 只告警、不拒写**：拒写的判断留在调用方（只有调用方知道能不能补价）。
   这与本文件第 3 节「别再默默写进去」不冲突 —— 现在**不默默**了。
3. **实盘侧未动**：`_sync_real_equity` 本来就对（日点 `_close_on_date` + 缺价不写），
   `_real_quotes` 也覆盖池外 ⇒ 无同类风险。
4. `data/full_market.db` 仍停在 **2026-09-22**（`scripts/35` 的下一次自动跑见
   `docs/2026-09-22-full-market-refresh-scheduled.md`；注意中秋/国庆休市日尚未填进
   `holiday_dates`，那一项**另案处理**）。
