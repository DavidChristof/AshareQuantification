# 判别实验：训练池的幸存者偏差是不是「模型前向 IC 接近 0」的主因？

**日期**：2026-09-22
**起因**：用户问「是否是我们的方向搞错了？也许是因子选择出的问题呢？」
**结论**：**幸存者偏差是主因 —— 配对级证据成立**
（日期对齐后，**配对** t = **+2.73**，n=91，同一天起止）。
无偏池训出的模型留出 IC **+0.0335（t=+3.11，站得住）**，有偏池那个 **+0.0140（t=+1.22，与 0 分不开）**。
**但 top-bottom 只从 -0.0006 抬到 +0.0040** —— 从负转正，绝对值仍小
⇒ 偏差解释了一部分，**「头部没有区分度」这个病没被治好**，学习目标那一轮仍然要做。

---

## 0. 先排除「因子选择」这个方向

排查发现**不是因子选择**的问题，证据是**三个模型的表现模式一致**：

| 模型 | 自己报告的留出 IC（后20%时间） | n | t | top-bottom | 27 的「全窗口」 |
|---|---|---|---|---|---|
| `model_v2`（线上40） | **-0.0138** | 316 | -1.23（不显著） | **-0.0041** | 0.0548 |
| `model_v2_large`（影子600） | **+0.0224** | 196 | +3.13 | **-0.0012** | **0.3702** |
| `model_v2_base1000` | +0.0365 | 193 | +2.85 | +0.0014 | — |

- **三套不同池子/规模的模型都落在同一个模式里**（IC 很弱、top-bottom ≈ 0 或负）。
  如果问题是「因子选得不好」，换池子/换因子暴露应该看到明显分化 —— 实际没有。
  共同点是**训练/标签/评估流程**，不是因子清单。
- **`0.3702` 是训练段记忆，不是能力**：训练脚本里写着 `验证段（后 20% 时间）`，
  而 27 的窗口含训练段 80%。真实差距是 **+0.0224 vs -0.0138**，比叙事小一个数量级。
- **top-bottom ≈ 0 或负**（比 IC 更致命）：选股只用头部。实测最近 8 日逐日截面，
  600 的头部十分位减底部十分位均值 **-0.6%**、40 池 **-0.5%** —— **两边头部都不如底部**。
- **并列假设已证伪**：逐日 598/598、599/599 全部唯一值，并列比 1.000 → 不是取整问题。

因子层面另有**真 bug，但都是「实现」不是「选择」**（本次未动）：
`scripts/40` 发现的「非基本面 top-40 的票 `total = fund_score` 未减半」；
`trd`（close/MA20-1，权重 0.15）在回测里是负贡献（去掉它基准 -10.8% → +46.3%）；
`selector.py:322` 硬编码 sh000300。

## 1. 实验设计（一次只动一个变量）

    A 对照 = 现有 559 池（现池40 ∪ large_pool）—— **幸存者偏差**
    B 处理 = PIT 中证500 层并集抽样 600 只 —— **无未来函数**

- **必须同 `--recent`**：现有跑批已经把「窗口长度」和「池子」混在一起了
  （同样 40 只票：全历史 IC -0.0138 vs recent1000 +0.0365），不同 recent 的比较无效。两组都用 `--recent 500`。
- **两组只数匹配**（599 vs 600）：把「横截面宽度不同」这个混淆也消掉。
- **不加现池 40 只**到处理组：那是「今天的名单」，会重新引入偏差。
- **不做 per-date 掩码**：`make_samples` 没有这个接口，而**并集本身就消除了幸存者偏差**
  （含后来被调出指数的票，正是偏差来源）。掩码只影响标签中位数与横截面构成，不影响无偏性。
  ⇒ 省掉对共享模块的改动。
- 标签/超参/成员**一律不变**。

### 为什么是「抽样 600 只」而不是全量 1048 只

内存实测：训练峰值随「**只数 x 天数**」走（大头是 Alpha101 因子面板 + `make_samples` 的 X，
不是模型本身）。全量 1048 只 @ recent500 需 **~9.8 GB**，而本机 15.6 GB、
常驻占用后只剩 4~6 GB —— **装不下**。抽样 600 只后与对照池同规模，内存可跑，
且因为是从无偏集合里**随机抽**，抽出来的子集仍无偏。抽样用**固定种子**（`_PIT_SAMPLE_SEED = 20260922`）可复现。

## 2. 结果

```
组                            留出IC     ICIR       t  top-bottom  n_days
A 对照(有偏) large500        +0.0190    0.153   +1.49     +0.0015      95
B 处理(无偏) pit500          +0.0429    0.418   +4.23     +0.0050     102

B - A：IC 差 +0.0239   se 0.0163   z = +1.47
```

成员分解：

| 成员 | A（有偏）IC | B（无偏）IC |
|---|---|---|
| lstm | +0.0144 | +0.0287 |
| transformer | +0.0450 | +0.0100 |
| gbm | +0.0156 | +0.0409 |

**读法**：

1. **无偏组自身统计上站得住**（t=+4.23），**有偏组站不住**（t=+1.49，与 0 分不开）。
   「一个成立、一个不成立」本身就是有方向的信息。
2. **但两组之差未达显著**（z=+1.47）—— 两个模型**分别独立训练**，比较的噪声远大于配对检验。
   要把结论升级成「配对级」，需要把两组钉在**同一段日期**上重训（见 §4 遗留）。
3. **top-bottom 只从 +0.0015 抬到 +0.0050** —— 改善了 3 倍多，但**绝对值仍然很小**。
   ⇒ 偏差解释了**一部分**，但「**头部没有区分度**」这个病**没有被治好**。
   这正是「学习目标只优化整体秩相关、不优化头部」的预测形态，那一轮仍然值得做。

### 验证段错位解释不了差距（反证）

`--recent` 是按**每只票自己的尾部**切的，而两池历史长度不同，所以验证段不完全重合：

```
large500  数据 2024-08-09~2026-09-22   验证段 ~2026-04-27 ~ 2026-09-22
pit500    数据 2024-06-14~2026-09-11   验证段 ~2026-04-07 ~ 2026-09-11
```

**反证**：若让重叠段的均值相等，则 pit500 多出的那 ~12 天需要日均 IC ≈ **+0.21**。
个股截面日 IC 到 0.2 是天文数字（本模型全部水平也才 0.04）⇒ **非重叠日不可能解释这个差距**，
差距只能来自重叠时段，也就是两组模型本身的差异。

## 2.5 升级：日期对齐 + **配对**检验（本次的最终结论）

### 2.5.1 先把两组钉在同一段日历上

`--recent` 是按**每只票自己的尾部**切，两池历史长度不同（large 到 09-22、full_market 到 09-11），
于是验证段错位。改用 `--start/--end` 按**日历**裁（新增参数）：

```
A large(有偏)   2024-09-02~2026-09-11 (492日)   验证段 2026-04-22~2026-09-11 (91日)
B pit500(无偏)  2024-09-02~2026-09-11 (492日)   验证段 2026-04-22~2026-09-11 (91日)
```

**完全同一天起止、n_days 都是 91** ⇒ 错位这个混淆彻底消掉。

对齐后：

| 组 | 留出 IC | ICIR | t | top-bottom | n_days |
|---|---|---|---|---|---|
| A large（有偏） | +0.0140 | 0.127 | +1.22 | **-0.0006** | 91 |
| B pit500（无偏） | +0.0335 | 0.326 | +3.11 | **+0.0040** | 91 |

> 注意：**对齐让差距略微变小**（+0.0239 → +0.0195），z 也从 1.47 降到 1.24。
> 说明那个验证段错位**并没有在夸大效应** —— 消掉它反而更保守。

### 2.5.2 关键：44 用的是**非配对**公式，高估了 se

`scripts/44` 用 `se = sqrt(se_A^2 + se_B^2)` —— 这丢掉了两个模型**逐日 IC 序列之间的相关性**。
而两组是在**同一天**上评价的，两串 IC 必然同向波动。正确的做法（同 `scripts/37` 的 `_paired`）
是对**逐日 IC 之差**做单样本 t。新增 `scripts/45_pool_bias_paired.py`：

```
共同可评日 n = 91      逐日 IC 序列相关 r = 0.798
A 平均 IC = +0.0140    B 平均 IC = +0.0335
逐日差 mean = +0.0195  sd = 0.0682
**配对**   se = 0.0071   t = +2.73   <- 显著
非配对     se = 0.0158   z = +1.23   <- scripts/44 的口径
丢掉相关性把 se 高估了 2.22 倍
```

### 2.5.3 结论升级

> **配对级证据成立：无偏池训出的模型显著优于有偏池（t = +2.73，n = 91，同一天起止）。**

**但要说清楚升级的来源**：不是效应量变大了（对齐后还小了一点），而是**修掉了口径错误**。
原来的「方向性证据」是**因为方法偏保守而被低估** —— 这个教训值得单独记（见 §5）。

**仍然成立的两条限制**：
- **top-bottom 只从 -0.0006 抬到 +0.0040** —— 从负转正，但**绝对值仍然很小**。
  「头部没有区分度」这个病没有被治好 ⇒ **学习目标那一轮仍然要做**。
- **绝对水平仍然弱**：0.0335 只是「统计上站得住」，不构成「可以上线」。

### 2.5.4 一个我自己踩的坑（差点又得出假结论）

`scripts/45` 第一版**没把评价裁到验证段** —— `make_signals_all` 对**整个窗口**出信号，
于是 462 天里大部分是**训练段**，算出来的平均 IC = **+0.52**（真实水平 0.03），
配对 t 还给出「显著」的**假**结论。

**这正是我在 §0 里指出 27 报 shadow600「样本内 0.3702」的同一个陷阱 —— 转头自己又踩了一遍。**
已修：复刻 `split_by_date` 的裁切口径，并加了一条护栏 —— **验证段均值 IC 若 > 0.15 就直接报警**
（真实横截面 IC 不可能到那个量级）。修好后验证段 IC 精确复现训练脚本报的 0.0140 / 0.0335。

## 3. 结论与建议

1. **幸存者偏差是主因之一 —— 配对级证据成立**（t=+2.73，n=91，同一天起止；见 §2.5）。既然如此：
   **`results/model_v2_large`（影子600）是在有偏的 559 池上训的**，
   它的弱前向 IC 有了统一解释。**「上线 600 模型」这个议程应当改成「在 PIT 无偏池上重训 600 模型再说」**。
2. **但别指望换池子就翻身**：无偏组的 IC 是 0.0335 —— 统计上成立，但**绝对值仍然很弱**
   （真实可用的横截面模型通常 0.03~0.06，这是在**同池评价**下的数，前向还要打折）。
   它**不构成「可以上线」的证据**，只说明「训练土壤该换」。
3. **下一轮测学习目标**：`relative` 标签（跑赢全池中位数）只优化**整体秩相关**，
   **不优化头部**，而选股只用头部。top-bottom 在换成无偏池后仍只有 0.0050，支持这个判断。

## 4. 必须一起看的局限

1. **PIT 中证500 与真实中证500 重合度仅 76.6%**（`docs/2026-09-11-pit-universe.md`）。
   它是「**无未来函数的同区间宇宙**」，**不是真实指数的复制品** ——
   只可用于**相对比较**。缓冲区规则与「总市值用流通市值代理」两项近似仍未实现。
2. **两组之差未达显著**（z=+1.47）。结论强度是「方向性证据」，不是「已确立」。
3. **验证段不完全重合**（见 §2 反证：不足以解释差距，但仍是瑕疵）。
4. **`full_market.db` 到 2026-09-11 为止**，比 `market.db` 的 09-22 旧 ~7 个交易日。
5. **处理组抽样了 600/1048** ⇒ 丢掉了 43% 的无偏票，方差更大。
6. **退市股拉不到**（约 241 只）⇒ 残余偏差无法补全；PIT 宇宙仍略偏乐观。
7. **一轮只动一个变量**：本结论只覆盖「池子」。学习目标那一轮尚未做。
8. **n_days 95/102、单一样本期（2026-04~09）** ⇒ 检验功效有限、且只有一个市场状态。

## 5. 本次踩的坑（都已修）

**① 我第一版的内存闸门低估 2.2 倍，形同虚设。**
我按「样本数 x X 大小 x 1.3」估，对 `large@recent500` 给出 2,096 MB —— 而**实测进程工作集是 4,690 MB**。
原因：内存大头是 `build_enhanced_features` 物化的 Alpha101 因子面板，它随「**只数 x 天数**」
增长，**不是**随样本数。已改成按**行数**线性外推、系数**实测标定**（16.2 KB/行，加 15% 余量）。
**这个错误值得单独记**：如果没撞上冒烟而是直接跑全量，会跑到一半 OOM、白等十几分钟。

**② GBK 护栏两次抓到我自己新写的代码。**
`scripts/44` 里用了 `-`(U+2212)、`²`(U+00B2)、`⇒`(U+21D2)；`scripts/18` 里用了 `⇒`。
这个仓库的控制台是 GBK，这些字符 `print` 会抛 `UnicodeEncodeError`。
**连我用来找这些字符的诊断脚本自己都崩了一次**（打印 `²` 时）。

**③ 判定条件写错一次。** 我最初用「谁越过 0.015 点估计门槛」来判，
但 A 的 0.0190 也**在门槛之上**、只是 t=1.49 说明它**与 0 分不开**。
**有区分度的是 t，不是点估计。** 已改。

**④ 用非配对公式比较高估了 se 2.22 倍 —— 差点把显著性判没了。**
`scripts/44` 用 `sqrt(se_A^2 + se_B^2)`，丢掉了两个模型逐日 IC 序列的相关性（实测 r=0.798）。
两组是在**同一天**上评价的，必须对**逐日之差**做配对 t。改用配对后 **t=+2.73（显著）**，
而非配对只给 z=+1.23。**「方向性证据」的定性本身就是这个口径错误造成的。**
⇒ 教训：**凡是 A/B 都在同一批样本上评价，就必须配对**，不能各自算 se 再合成。

**⑤ 评价没裁到验证段，算出 IC=0.52 的假数（见 §2.5.4）。**
我前脚刚在 §0 指出 27 的「样本内 0.3702」是训练段泄漏，后脚自己在 `scripts/45` 里踩了同一个坑。
⇒ 已加护栏：**验证段均值 IC > 0.15 直接报警**（真实横截面 IC 不可能到那个量级）。
