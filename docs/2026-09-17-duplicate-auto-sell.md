# 总资产凭空多了 9,898 元 —— 同一笔持仓被自动卖出两次（并发 TOCTOU）

**日期**：2026-09-17
**起因**：用户报「总资产怎么突然这么多了？而且还没开盘，模拟成交怎么会有 17 日的记录？」
**结论**：两个症状是**同一个 bug 的两面**。`sell()` 的「校验持仓」与「扣款」不在同一个写事务里，
而止盈止损被挂在**两个 GET 接口**上、被看板并发轮询 ⇒ 同一笔 400 股被卖了 800 股。
多卖的 400 股**凭空造出 9,898.02 元现金**。

---

## 1. 症状

`paper/manual_account.db` 的 `paper_trades` 里出现**两条逐字节相同**的卖出：

```
(20, '2026-09-17', '000792', 'sell', 400.0, 24.74505, 7.918416, 9898.02, '移动止损：从高点26.97回撤7.6%')
(21, '2026-09-17', '000792', 'sell', 400.0, 24.74505, 7.918416, 9898.02, '移动止损：从高点26.97回撤7.6%')
```

而该股**只有 400 股**（09-08 买 300 + 09-16 买 100）。

```
现金      82,768.44  ->  102,548.64   = +19,780.20   （= 两次卖出的净额之和）
只卖一次应为               92,658.54
总资产    98,732.44  ->  108,781.64   = +10,049.20
其中凭空造出的                       9,898.02       （= 多卖的 400 股 × 24.74505）
```

## 2. 为什么会有「没开盘的 09-17 成交」

三个因素叠加：

1. **`_apply_manual_stops()` 没有交易时段判断。** `manual_order` 有开盘校验，它没有 ——
   任何时刻被调用都会**真下单**。
2. **它被挂在两个 GET 接口上**：`/api/manual/account` 与 `/api/manual/positions`。
   看板一轮询就触发。这是「**检查动作本身带副作用**」，本项目第 3 次踩。
3. **价格是昨收、日期是今天**：盘前 `price=0`，`_live_prices()` 回退到信号表收盘
   （09-16 的 24.75），而 `trade_date()` 给的是**日历日** 09-17。
   ⇒ 昨天的价、今天的日期、今天的开盘之前。

## 3. 为什么会卖两次：TOCTOU 竞态

FastAPI 把同步端点丢线程池，两个 GET 同时进来，于是：

```
线程A: SELECT 持仓 -> 400 股 ✓ 判定「持仓足够」
线程B: SELECT 持仓 -> 400 股 ✓ 判定「持仓足够」     <- 都还没写回
线程A: BEGIN; UPDATE cash += net; DELETE 持仓; COMMIT
线程B: BEGIN; UPDATE cash += net; DELETE 持仓(0 行); COMMIT   <- 现金被贷记第二次
```

原来的 `sell()` 是「**一个连接 SELECT 校验 → 另开连接 BEGIN 更新**」，
`BEGIN` 在 SELECT **之后**，校验与扣款**不在同一个事务**里 —— 典型 TOCTOU。

```

删除：paper_trades id=21
现金：102,548.6417155995 -> 92,658.5401315995
```

**保留 id=20** —— 移动止损本身是**合法触发**（持仓期最高价 26.97，
× (1−8%) = 24.81，现价 24.745 已跌破），400 股全平是对的，错的只是**卖了两次**。

核对：`82,768.4385475995 + (9898.02 − 7.918416) = 92,658.5401315995` ✓
正好等于「09-16 收盘现金 + 一次卖出的净额」。

## 5. 代码修复

### 5.1 `quant/trading/paper.py::sell()` —— 校验与扣款进同一写事务（根治）

```python
with self._connect() as conn:
    conn.execute("BEGIN IMMEDIATE")          # <- 先拿写锁，再读持仓
    pos = conn.execute("SELECT shares ...").fetchone()
    if pos is None or float(pos[0]) < shares - 1e-6:
        conn.rollback(); return ...「持仓不足」
    ... T+1 校验 ...
    conn.execute("UPDATE paper_account SET value = value + ? ...")
```

`BEGIN IMMEDIATE` 让第二个调用**等在写锁上**（sqlite3 默认 `timeout=5s`），
拿到锁时读到的已是更新后的持仓 ⇒ 正确返回「持仓不足」。

### 5.2 `api/main.py::_apply_manual_stops()` —— 加串行锁（第二道防线）

```python
_manual_stops_lock = threading.Lock()

def _apply_manual_stops(_live=None):
    with _manual_stops_lock:
        return _apply_manual_stops_locked(_live)
```

顺带避免同一轮重复触发与重复写库。

### 5.3 回归测试 `tests/test_paper_atomic.py`（4 条）

核心是 `test_concurrent_sell_does_not_oversell`：8 个线程用 `Barrier` 同时全平同一笔持仓。

**已确认这条测试「有牙」**：把 `paper.py` 还原成旧版本再跑，它报了

```
AssertionError: 同一笔 400 股持仓被成交了 3 次（应恰好 1 次）
```

—— 在测试环境里**现场复现了生产事故**。改回修复版后 4/4 通过。

## 6. 一个没改的显示 bug

`/api/real/account` 在 09:23 报「**今日已收盘 09:23**」。
`_market_status` 把「快照是今天的、但不在 09:30–15:00 之间」一律当成 `closed_today`，
**集合竞价/盘前被归进去了**。应为「盘前」单独一档。本次未改。

## 7. 遗留

1. **`buy()` 有一模一样的 TOCTOU**（`cash = self.query_cash()` 在事务外，
   然后 `BEGIN` + 扣款）⇒ 并发买入可以**透支现金**。本次**只按要求改了 `sell()`**，
   `buy()` 未动 —— 同样一行 `BEGIN IMMEDIATE` 就能修。
2. **GET 里有副作用**（本次事故的根因之一，只加了锁、没搬家）：
   止盈止损应当挪到后台线程或显式 POST。
3. 自动止盈止损**仍无交易时段判断**，盘前仍会用昨收价下单（只是不会再重复卖）。
4. `_market_status` 的盘前文案（见第 6 节）。

## 8. 教训

1. **「先校验、后写入」在两个连接之间 = 没有校验。** 校验必须和写入**在同一个事务、
   同一个写锁**里，否则并发下等于没写这段代码。**这条要当写账本代码的硬规矩。**
2. **GET 不该改状态。** 这次不是"顺手写坏了"，是**架构上**把下单放进了读接口 ——
   副作用一旦挂在轮询路径上，触发频率就是**每秒级**，任何竞态都会被放大。
3. **同一个函数被两处轮询 = 天然的并发测试。** 事后看，`/api/manual/account` 与
   `/api/manual/positions` 同时调 `_apply_manual_stops` 简直就是把并发 bug 摆在明面上，
   而它这么写了 9 天都没人发现（因为**只有在恰好触发止损的那一刻**才会冲突）。
4. **账本类 bug 的发现方式是"数字对不上"，不是"报错"。** 全程没有任何异常、
   没有任何日志告警 —— 是靠人眼看出「总资产怎么突然这么多」。
   ⇒ 账本应加**恒等式护栏**：`现金变动 == Σ成交净额`，跑批后自动核对。
5. **测试要能复现事故才有价值。** 本次特意把修复回滚验证测试会失败 ——
   「新测试第一次全绿」不能说明它测到了东西。
