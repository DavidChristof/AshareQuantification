# 看板显示的止损线，不是实际会触发的那条

**日期**：2026-10-20
**起因**：用户问「洛阳钼业已经到达止损线，为什么没有卖出」。
**结论**：**没卖是对的**（止损按收盘价判，上一根收盘 15.43 离两条线都还远）；
但查出**展示层少算了一条线**：卡片上的「止损线」只是**成本止损线**，而撮合层
实际会**先**触发**移动止损线**（高点回撤）。两者取**更高**的那条。
**已修**：`_position_risk` 返回真正生效的线 + 前端显示它；并订正两处与实现不符的 docstring。
**未修（单议）**：止损的**成交价**用的是上一交易日收盘价（见 §5）。

---

## 1. 先回答「为什么没卖」

洛阳钼业（603993）600 股，成本 15.729：

| | 价格 | 与判据的关系 |
|---|---|---|
| 成本止损线 `cost*(1-sl)` | 14.228 | 上一根收盘 15.43 比它**高 8.4%** |
| 移动止损线 `high*(1-trail)` | **14.739** | 上一根收盘比它**高 4.7%** |
| 上一根收盘（10-19，**判据用的价**） | 15.43 | 两条线**都没到** |
| 当日盘中价 | 14.02 | 盘中跌破，但**盘中不触发** |

判据见 `quant/trading/paper.py::apply_stop_rules`，而 `api/main.py::_apply_manual_stops_locked`
给**止损那一趟**传的是 `close_prices`（`SIGNALS` 最后一根收盘），不是实时价 ——
这是 2026-09-08 定的口径（盘中插针不打损），依据是：
**2.5×ATR 盘中触发 -> 止损后 10 日 +1.25%（被震出）；3.0×ATR 收盘触发 -> -0.35%（切对了）**。

⇒ 若 10-20 收在 14.74 以下，**10-21 盘中**第一轮巡检（每 30 秒）就会卖出。

## 2. 发现①：展示的止损线 ≠ 实际生效的线

`_position_risk` 原来只算 `cost*(1-sl)`，**完全没算移动止损**；而 `apply_stop_rules`
三条线里，**价格下跌时先碰到的是价格更高**的那条：

```
触发价 = max( cost*(1-sl),  high*(1-trail) )     # high = 持仓期间最高价
```

实测 2026-10-20 的 5 只持仓，**生效线全部是移动止损线**，显示的那条**每一只都偏低**：

| 代码 | 成本线（原显示） | 回撤线（实际生效） | 差 | 现价距生效线 |
|---|---|---|---|---|
| 603993 | 14.228 | **14.739** | +3.6% | **-4.9%** |
| 002027 | 4.765 | 5.026 | +5.5% | **2.7%** |
| 002602 | 11.153 | 11.474 | +2.9% | 5.3% |
| 600809 | 110.646 | 112.162 | +1.4% | 3.8% |
| 002709 | 25.250 | 25.641 | +1.5% | 8.7% |

后果是**双向**的：以为"还远"（本例），以及在真实触发时看到"没到显示的线却卖了"。
另外 `stop_dist` 也是按成本线算的，所以「距止损 ≤3% 亮警戒」这个标签**一直偏迟钝**
（002027 真实只剩 2.7%，按旧算法却是 8.3%）。

## 3. 修复

| # | 位置 | 改动 |
|---|---|---|
| 1 | `quant/trading/base.py::Position` | 加 `max_price: float = 0.0`（移动止损的参考价）。原来 `Position` 不带它，展示层**根本拿不到高点** |
| 2 | `quant/trading/paper.py::query_positions` | SELECT 里补 `COALESCE(max_price,0)` |
| 3 | `api/main.py::_position_risk` | 新增 `max_price` 参数；按**与 `apply_stop_rules` 同一公式、同一前提**（`high > cost`、`trailing_enabled` / `trailing_stop`）算出 `trail_price`；返回 `trail_price` / `eff_stop_price`（= `max(成本线, 回撤线)`）/ `eff_sl_pct` / `stop_basis`（`fixed` 或 `trailing`） |
| 4 | `api/main.py::manual_positions` | 传 `max_price`；透出上面四个字段；`stop_dist` 改按 **eff** 算（「警戒」标签才准） |
| 5 | `frontend/index.html`（持仓表止损列） | 显示 **eff_stop_price**；生效的是回撤线时加「高点回撤」标签；`title` 悬停同时给出成本线与回撤线 |

## 4. 发现②：docstring 与实现不符（已订正）

`_apply_manual_stops_locked` 原文：「**止损仅在收盘数据刷新后触发一次**」。
但实际上：`SIGNALS` 在**收盘后 16:45** 才刷新，而巡检**只在交易时段跑**
（`_in_trading_hours` = 09:30-11:30 / 13:00-15:00）—— **两者永远错开**。

真实行为：**用上一交易日的收盘价，在下一交易日盘中触发**。
（行为本身是合理的：收盘后不能交易，close 触发的止损必然落到下一个可交易时点。）
已把这段写进 `_apply_manual_stops_locked` 与 `apply_stop_rules` 的 docstring。

## 5. 未修：止损的**成交价**（单议）

`apply_stop_rules` 触发时执行 `self.sell(pos.symbol, pos.shares, price, date, ...)`，
`price` 就是判据用的那个**收盘价**。于是：**成交日期是下一交易日，成交价却是上一交易日收盘**。
次日若跳空低开，账面按更高价成交 => **对止损偏乐观**。
`logs/risk_sold_*.json` 在 10-08/09/12/13/15 都出现过，说明已经发生多次。

**没动的原因**：换成「次日实时价」更真实，但会与所有历史回测口径（close-to-close）
不再可比，需要单独评估。**本轮只修显示与文档，不碰成交价。**
