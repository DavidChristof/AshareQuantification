# 大盘趋势闸门的「口径」问题 —— 用上一交易日的大盘判今天，以及回测/实盘不自洽

**日期**：2026-09-14
**起因**：用户问「根据上一交易日的大盘来判定当日是否交易保护，是否有些过于保守？」
**结论**：怀疑成立。但**比"保守"更严重的是回测口径与线上口径不是同一个**。
本次只做**第一层（口径自洽）**，第二层（该不该留 / 怎么放宽）需要重新回测。

复现：`.venv/Scripts/python.exe scripts/41_trend_gate_study.py` → `results/trend_gate_study.json`

## 1. 复核：确实用的是上一交易日的收盘

`quant/risk/market_trend.py::trend_gate()` 取 `level = closes[-1]`，
而 `fetch_index_daily`（新浪 `stock_zh_index_daily`）是**日线**接口 ——
**盘中不含当天、收盘后含当天**。

实测（2026-09-14 13:30 盘中，交易日进行中）：

```
fetch_index_daily("sh000300") 最后 3 行：
   2026-09-09  4572.600
   2026-09-10  4548.390
   2026-09-11  4510.155      <-- 最后一根 = 上一交易日
闸门报出的 level = 4510.15     <-- 完全一致
而 /api/market/indices 有实时点位 4480.89（数据在手边，闸门没用）
```

⇒ 配置里写的「指数跌破 MA20 → 当日不开新仓」，实际执行的是
「**昨天收盘**跌破 MA20 → 今天不开新仓」。

## 2. 量化（沪深300，2020-01-02 ~ 2026-09-11，1624 个交易日）

### 2.1 「当日不开新仓」的比例 —— 保守程度

| 口径 | 阻断率 |
|---|---|
| 现状：昨收 vs 昨日 MA20 | **51.0%** |
| 实时：今开 vs 昨日 MA20 | 52.4% |
| 回测：今收 vs 今日 MA20 | 51.1% |

逐年（现状口径）：

| 2020 | 2021 | 2022 | 2023 | 2024 | 2025 | 2026 |
|---|---|---|---|---|---|---|
| 28.4% | 55.1% | **67.4%** | 64.5% | 56.2% | 34.6% | 51.5% |

**一半的交易日不开新仓**，2022 年高达三分之二。就字面意义而言，"过于保守"是成立的。

### 2.2 滞后一天本身的代价 —— **不大**

| 指标 | 值 |
|---|---|
| 现状口径 vs 实时口径 一致率 | **94.3%** |
| 假阻断（今天已站回均线上方却仍被拦） | 35 天 / **2.2%** |
| 漏放（今天已跌破却仍放行） | 57 天 / **3.5%** |

均线状态高度自相关，所以「用昨天的数据」**本身**不是主要矛盾。

### 2.3 回测口径 vs 线上口径 —— **这条最要命**

`scripts/37_risk_rerun_pit.py:200-201`：

```python
ma20 = idx.reindex(dates).rolling(20).mean()
ma_ok = (idx.reindex(dates) >= ma20)      # 今收 vs 今日MA20，且按今收成交
```

而线上闸门在 09:31 只能用 **昨收 vs 昨日 MA20**。

**两种口径在 209 个交易日 / 12.9% 上给出相反结论。**

⇒ 三个后果：
1. 当初验证出「熔断+闸门 7.4% / Sharpe 0.57」的那个信号，与线上真正在跑的不是同一个；
2. **`close(D)` 收盘后才知道 ⇒ 回测验证的是一个实盘无法落地的信号**；
3. 同一个交易日内，**09:31 自动调仓**（昨收口径）与**收盘后看板/手动**（今收口径）
   有 12.9% 的概率给出相反建议 —— 同一个面板自相矛盾。

### 2.4 拦得对不对（不重叠 5 日窗口，避免重叠放大显著性）

| | n | 未来 5 日沪深300均值 |
|---|---|---|
| 阻断日 | 165 | **+0.19%** |
| 放行日 | 159 | **−0.07%** |
| 差 | | +0.26pp，**t = +0.84** |

⇒ **没有证据表明"拦了更好"**；点估计方向还相反，但 t 不显著，**不能据此下结论**。
（这是**指数**口径，不等于策略口径。）

再加上此前的更重证据：**PIT 无偏宇宙重跑（`docs/2026-09-11-risk-control.md` 修正③）
没能复现趋势闸门的收益改善**（老池帮倒忙、PIT 帮忙，跨宇宙不一致）。
⇒ 这个闸门的实证基础本来就薄弱，**第二层应重新回测后再决定去留**。

## 3. 第一层修复（本次已做）：口径自洽

新增纯函数 `quant/risk/market_trend.py::completed_closes(dates, closes, today)`：

> 只保留 **`today` 之前** 已收盘交易日的收盘价。今天及以后一律剔除。

`_market_trend_gate()` 改用它，并在返回值里加 `as_of`（闸门基于哪一天的收盘，可核对）。

于是闸门对「今天」的口径唯一：

```
盘中 09:31 （数据只到 D-1）  -> 用 D-1
收盘后 15:30（数据含 D）     -> 剔除 D，仍用 D-1     <-- 修复点
次日 09:31 （数据含 D）      -> 用 D                 <-- 自然前进一根
```

**为什么"剔除今天"才是对的**：闸门的语义是「**当日**不开新仓」，而当日所有实际调仓
（09:31 自动、盘中手动）都发生在收盘之前 ⇒ 只能用 `close(D-1)`。
写死成「今天之前」之后，同一交易日内无论何时求值都得到同一答案，
且**结构上不可能有未来函数**（`today` 之后的数据一并剔除）。

**行为影响**：**盘中零变化**（本来就只有 `D-1` 可拿）；变化的只是**收盘后看板显示的口径**
——现在与当日实际约束交易的口径一致了。所以这是纯正确性修复，不改变保守程度。

实测（修复后）：

```json
"market_gate": {
  "level": 4510.15, "ma": 4593.13, "ma_days": 20, "below": true,
  "reason": "大盘 4510.15 跌破 20 日均线 4593.13（低 1.81%）→ 当日不开新仓",
  "index": "sh000300", "as_of": "2026-09-11"        <-- 新增，明确标出依据
}
```

在改动前后构造一个会翻转的例子（前 19 天 5000 → 09-11 跌到 4500 → 09-14 当天反弹到 5200）：

```
旧实现： 盘中 below=True   /  收盘后 below=False    <- 同一天相反结论  [X]
新实现： 盘中 below=True   /  收盘后 below=True     <- 一致          [OK]
次日：   纳入 09-14 的收盘 5200
```

## 6. 教训

1. **"日线接口"不等于"盘中就有今天"**：`fetch_index_daily` 盘中只到昨天、收盘后才含今天。
   凡是用日线做**当日**判断的地方，都要显式回答"我要的是哪一天"。
2. **回测口径必须与实盘可执行口径一致**。回测用当日收盘、实盘在开盘执行，
   等于验证了一个落不了的信号 —— 收益再漂亮也不算数。
3. **口径漂移比参数错误更隐蔽**：同一个函数，同一天，上午和下午给出相反答案，
   而两边各自的日志看起来都"正常"。
4. **把依据写进返回值**（本次加了 `as_of`）。今天这场困惑，本质上就是
   「闸门报了个 4510.15，没人知道这是哪天的」。
