# 影子 A/B 加了「显著性」闸门 —— 点估计领先不算稳压

**日期**：2026-10-22
**起因**：10-19 / 10-20 / 10-21 连续三天 `scripts/28` 报 **STABLE**（四项判据全 OK），
按既定流程该提醒「可以上线 600 池」。复核后**没上线**。
**结论**：前四条判据全是**点估计比较**，不含任何显著性检验；同一批数据的配对检验
`t=+0.82 (p=0.42)`，**分不出差别**。所谓"交叉"是**一次 regime 反转**。
**改动**：`scripts/28` 新增第 5 条判据「配对 t(HAC) ≥ 2」。

---

## 1. 发生了什么

```
10-19  n=19  40: IC 0.0962 ICIR 0.697   600: IC 0.1032 ICIR 1.009   -> STABLE
10-20  n=20  40: IC 0.0887 ICIR 0.640   600: IC 0.1050 ICIR 1.051   -> STABLE
10-21  n=21  40: IC 0.0849 ICIR 0.622   600: IC 0.1051 ICIR 1.080   -> STABLE
```

而 10-15 / 10-16 还是 NOT_YET（600 的**平均 IC** 输）。**三天内翻了面。**

## 2. 复核：配对检验说"没差别"

逐日 RankIC 差（600 − 40），n=21：

```
均值差 = +0.0202/期    普通 t = +0.82    p = 0.42
符号检验：600 赢 12/21 天
```

**逐日差异的形状**才是关键 —— 它是**两次干净的翻转**，不是"稳定地略优"：

| 区间 | 逐日差值 | 含义 |
|---|---|---|
| 09-08 ~ 09-11 | + + + + | 600 赢 4 天 |
| 09-14 ~ 09-24 | - - - - - - - - - | **40 连赢 9 天**（40 的日 IC 高到 0.13~0.33）|
| 09-28 ~ 10-14 | + + + + + + + + | **600 全赢 8 天**（40 的日 IC **转负** -0.056~-0.083）|

⇒ 累计均值交叉，是因为 **40 在 10 月转负**，而 600 保持 +0.06~+0.13。
**点估计规则在行情反转时必然误报一次。**

## 3. 更狠的一层：天数根本没那么多个"独立观测"

每天的 RankIC 用的是**未来 5 日收益**，相邻两天共享 4/5 的收益窗口 ⇒ 序列正自相关。
普通 t 把 n 天当成 n 个独立样本，**系统性高估**显著性：

```
普通 t        = +0.82
HAC(lag=4) t  = +0.44      <- 自相关修正后只剩一半
```

n=21 天，有效独立观测大约只有 **n/5 ≈ 4 个**。

## 4. 改动（`scripts/28_shadow_check.py`）

| 改动 | 说明 |
|---|---|
| 新增 `hac_t(diff, lag)` | Newey-West / Bartlett 权重的 HAC t 值；`lag = horizon-1 = 4` |
| 新增第 5 条判据 | `600>40(配对t>=2)`：要求**600 显著领先**，不只是领先 |
| **fail closed** | 样本太少 / t 算不出来 ⇒ 判据**不通过**（宁可多等，不能因为"没算"而放行） |
| 打印配对统计 | 均值差、`t(HAC)`、600 赢的天数、重叠说明 |
| NOT_YET 说清卡点 | 卡在显著性时明确写出 `t=+0.44 < 2`，并注明重叠窗口 |
| 新 CLI | `--min-paired-t`（默认 2.0）、`--hac-lag`（默认 4） |

**为什么门槛取 2.0**：这是单侧检验（且第 3 条已要求 `m60 > m40`，符号为正），
`|t| >= 2` 与 `t >= 2` 在此等价，约对应 p < 0.025。

- **UTF-8 与真实 GBK 控制台都跑通**（不带 `PYTHONIOENCODING` 实跑，rc=1、无

  一旦含非 GBK 字符，结论永远打不出来。
- `tests/test_gbk_output.py` 4/4；全量 `tests/test_*.py` 31/31。

## 6. 影响与已知代价

1. **STABLE 会变得很难触发** —— 这是**意图**（前四条规则在 regime 反转时会误报）。
2. **可能的副作用**：如果 600 真的只比 40 好一点点，这个闸门会长期不通过。
   按当前效应量（0.020/期）与噪声，要 `t(HAC)=2` 需要约 **6 倍**样本
   ⇒ 有效观测 ~25 个 ⇒ **125 个交易日 ≈ 半年**。
   **这是诚实的代价**：要么等，要么用别的证据（例如成本/回撤这类粗颗粒判据）。
3. **可评数据只到 2026-10-14**（`ret5` 要 5 天后才有）—— "累积 OOS 26 天" 里
   真正带收益的只有 21 天，别把天数当信息量。

## 7. 本次复核排除了哪些"错误解释"

| 假设 | 检查 | 结论 |
|---|---|---|
| `ret5` 是后向收益（用错方向） | `ret = close.shift(-5)/close - 1` | **前向** ✓ 排除 |
| 脏数据/极端值把 IC 拉高 | 09-22 与 10-09 的 `ret5` 分布（p50 -3.3%、p1 -18%、p99 +9.6%、无 >0.5） | 正常 ✓ 排除 |
| 模型被重训导致 OOS 不再 OOS | `model_v2` 09-03 / `model_v2_large` **09-07 22:12**，cutoff `>09-07` | 未越界 ✓ 排除（但只差 6 小时，记录在案）|
| 每日 5 日 RankIC 高达 0.33 本身可疑 | 与仓库自测的线上综合分同口径峰值 **0.022** 相比高 15 倍 | **无法解释为 bug，但记下**：说明那段截面动量极强、模型吃到了；也正因如此，**这种日子上的领先最不可外推** |
