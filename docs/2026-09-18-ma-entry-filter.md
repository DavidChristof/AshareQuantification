# 关闭大盘趋势闸门 + 个股 MA 入场过滤器对照回测

**日期**：2026-09-18
**起因**：用户问「以大盘趋势作为闸门是不是不够准确？是否应该以个股的 ma5 和 ma20 作为闸门？」
**结论**：两件事分开处理，都有结论。
① 大盘闸门**已关闭**（`enabled: false`）—— 它的实证支持在 09-16 已被口径对齐证伪。
② 个股 MA 当入场过滤器**不成立**：「站上均线才买」方向 **18/18 为负**（控制组 16/18），
   不是无效而是**有害**；「回踩才买」方向符号不一致，与噪声一致。**不引入。**

---

## 0. 先把两件事分开：它们不是替代关系

用户的提问里隐含了一个假设：个股 MA 是「更准的大盘闸门」。**不是。** 它们管的东西不同：

| | 大盘闸门 | 个股 MA |
|---|---|---|
| 管什么 | **总仓位 / 系统性风险** | **选谁 / 何时买** |
| 粒度 | 全账户一个开关 | 每股一个开关 |

大盘跌时**持仓相关性趋近 1、分散化失效** —— 此时一个指数信号恰恰是**对**的工具。
换成个股 MA 等于**放弃仓位控制**：崩盘时只要某只票还在 MA5 上方，照样满仓买进去。

所以本次不是"换一个闸门"，而是**关掉旧闸门 + 独立检验一个新机制**。

## 1. 关闭大盘趋势闸门

### 改动

```yaml
market_trend_gate:
  enabled: false      # 原 true
  index: sh000300
  ma_days: 20
```

**不需要改任何代码** —— `enabled` 在 `api/main.py:2337-2339` 被正确读取，且在缓存与网络
调用**之前**返回；关掉后既不发指数请求，也不写 30 分钟缓存。

### 关闭后失效的是哪些行为（已逐处核对）

| 位置 | 原行为 | 关闭后 |
|---|---|---|
| `api/main.py:1900`（`_portfolio_allocation`） | 跌破 MA20 → 新开仓 `action="skip"` | 不再拦截 |
| `quant/trading/real_advice.py:164` | 同上，实盘建议的新买入被跳过 | 不再拦截 |

**不受影响**（都是独立机制，逐个确认过）：加仓/减持、止损、回撤熔断、
`_market_weakness` 弱势降仓（无 `enabled` 开关，靠 `market_weak_threshold` / `weak_trim`）、
以及 selector 的市场状态权重（独立开关 `selection.regime_gating`）。

### 为什么关（三次独立证据，详见 09-16 文档）

1. 原来那条「加闸门 7.4%/Sharpe 0.57」是**未来函数**测出来的：回测用**当日收盘**算 MA20，
   而闸门 **09:31 执行**，当时不可能知道当日收盘。口径对齐后改善消失
   （pit 宇宙：熔断 −31.4% → 加闸门 −32.9%，Sharpe −0.36 → −0.73）。
2. 配对 t 检验（239 期，只差闸门一个开关）：**6/6 不显著**，t 在 −0.51 ~ +0.15，
   符号随宇宙/指数翻转。累积不确定度 ±37~45pp —— 总收益上 10~25pp 的差异**不到一个标准误**。
3. MA20 阻断率 **51.1%** —— 一枚硬币。

**同时订正了配置注释**：原注释照抄了那个被证伪的 7.4%/0.57，留着会让下一个人照着假数据
再打开。现在注释写明关闭理由与指向文档。

## 2. 个股 MA 入场过滤器对照回测（新增 `scripts/43`）

### 2.1 既有研究留下的空白

`docs/2026-09-11-score-lag-and-entry-gate.md` 在大池 top12 上测过入场闸门（等回踩 ≤MA5：0.50%）。
两个空白：**(a) 那是有幸存者偏差的池子**（+97.9pp）；**(b) 只测了"回踩"，没测"站上"** ——
而"站上"才是用户这次提的方向。

### 2.2 设计（三个选择都是为了不让结论被混淆骗掉）

**① 两个方向都测**：站上（`close>MA5` / `close>MA20` / `MA5>MA20`）、回踩（`close<=MA5` / `<=MA20`）。

**② 三种持仓口径**，因为它们的混淆**不同**：

| 口径 | 语义 | 混淆 |
|---|---|---|
| `cash` | topN 不变，未通过**且未持有**的仓位留现金（= 线上闸门「不开新仓、保留持仓」原义） | 同时**降低了仓位暴露** |
| `filter` | 先按分取 topN，再剔掉未通过的 | **只数变少**（分散度改变） |
| `refill` | 先在通过集合里排名再取 topN | 只数保持，但**成员变了** |

三种都报并给出**平均实际只数**，让「分散度/暴露被改变」这个混淆**可见**。

**③ 两个宇宙 + trd 控制组**：large（有偏，与既往可比）/ pit（无偏，本项目判据）。
`--no-trd` 把 `build_score` 里 `trd = z(close/MA20-1)`（权重 0.15）置 0 后归一 ——
因为「`close>MA20`」这个过滤器与 alpha **本身部分同向**，不控制会把「重复计分」当「过滤器有效」。

### 2.3 口径

与 `scripts/37` 逐字对齐：`REBAL=5`、`COST=0.0016`、topN=12 等权、`close[d] -> close[d+5]`。
开始日 `2021-07-01`（37 的默认）。无未来函数：过滤器、打分、成交都只用到 `close[d]`。
（注意这与大盘闸门的「09:31 口径」不是一回事：那个是**日内执行**故必须以 D-1 为准；
这里是**收盘执行**，用 `close[d]` 不算偷看。）

### 2.4 结果（239 期，paired t，`large/pit`）

主口径（`trd=on`）：

| 过滤器 | 方向 | cash t | filter t | refill t |
|---|---|---|---|---|
| above_ma5 | 站上 | −1.32 / −1.25 | −0.86 / **−2.33** | −0.97 / −1.30 |
| above_ma20 | 站上 | −0.86 / −0.87 | −0.76 / **−2.04** | −0.58 / −0.67 |
| ma5_gt_ma20 | 站上 | −1.17 / −0.98 | −1.23 / −1.28 | −0.94 / −1.17 |
| below_ma5 | 回踩 | −0.53 / +0.99 | +1.22 / +1.48 | +0.32 / +1.84 |
| below_ma20 | 回踩 | −0.57 / +0.73 | +0.65 / **+2.15** | +1.59 / **+2.34** |

控制组（`trd=off`，排除"与 alpha 同向"的混淆）：

| 过滤器 | cash t | filter t | refill t |
|---|---|---|---|
| above_ma5 | −0.88 / −1.01 | **−2.38** / −0.81 | −0.75 / −1.88 |
| above_ma20 | −1.16 / −0.45 | +0.01 / −0.73 | −0.55 / −1.82 |
| ma5_gt_ma20 | −1.38 / −0.89 | −0.57 / +0.02 | −0.90 / −1.88 |
| below_ma5 | −1.20 / −0.82 | +0.85 / +1.42 | −0.68 / −0.23 |
| below_ma20 | −0.96 / −1.58 | +1.00 / +0.41 | +1.09 / +1.04 |

### 2.5 结论

**① 站上方向：一致为负，且不是"无效"而是"有害"。**

主口径 **18/18 个 t 全部为负**；控制组 **16/18 为负**，另 2 个是 +0.01 / +0.02（等于零）。

单看每个 t 大多不到 2（配对检验功效低，见 §2.6），但**方向一致性**本身是强证据：
18 格同向为负，符号检验 p ≈ 7.6e-6。幅度也大 —— pit 基准 −59.8%，
加「站上 MA5」过滤后 **−86.2%**。

⇒ **用户提的方向（站上均线才买 / MA5>MA20 多头排列）经检验是负贡献。**

**② 回踩方向：符号不一致，与噪声一致。**

`cash` 口径偏负、`filter`/`refill` 偏正（4/4 正但都弱，最大 t=+2.34）。
全表 30 个检验里 **4 个 |t|≥2，随机预期约 1.4 个**，且方向互相矛盾
（2 负 2 正，全在 pit）⇒ 没有可辨识的信号。

**③ 与大盘闸门在同一把尺子下的结论一致：没有可验证的价值。**

值得注意：回踩方向**唯一**有点弱正向证据，而它**已经以 advisory 形式存在于
`advice.entry_gate`**（现价高于 MA5 → 不追、标"等回踩"，`config.yaml:187`）。
也就是说 —— **不需要新增机制，已有的那个已经覆盖了唯一有点数据支持的方向。**

### 2.6 必须一起看的局限

1. **pit 基准本身巨亏**（−59.8% / 年化 −16.9%）。在一个大幅亏损的策略上做过滤器叠加，
   统计功效很低 —— 这削弱了**所有**单格结论的强度（09-16 文档已记录同一局限）。
   「站上方向一致为负」是本次唯一**不依赖单格功效**的结论，因为它靠的是符号一致性。
2. **`cash` 口径混淆了"何时买"与"降仓位"**：熊市里任何减仓都显得好。故三个口径并列，
   不以 `cash` 单独下结论。
3. `large` 池有幸存者偏差，绝对值不可信；它在本表中主要充当**第二个独立样本**。
4. **「没有证据表明有效」不等于「证明了无效」。** 只能说：现有证据不支持引入。

## 3. 本次踩的坑（都已修）

**① 在掩码后的面板上算均线，会被 NaN 污染。**
`load_pit` 用「非成分股置 NaN」模拟宇宙限制。若直接在它上面 `rolling(20).mean()`，
一只票**重新进入成分**后的 20 天内 MA 全是 NaN，过滤器把它误判成「不通过」。
个股均线是它**自己价格序列**的属性，不该受成分变动影响
⇒ 改为在**掩码之前**的收盘价上算均线（`load_pit` 第三个返回值）。

**② 过滤器与 alpha 同向的"重复计分"。**
`build_score` 里 `trd = z(close/MA20-1)` 权重 0.15 → 「`close>MA20`」这个过滤器与
alpha 部分同向。不控制的话，测出来的可能是"重复计分"而非过滤器的贡献 ⇒ 加 `--no-trd` 控制组。

**③ 汇总表的列宽不够。**
每格内容是 `-1.03/-0.55`（11 字符），我给了 9~10 列宽 → 三格挤成一串
（`-1.03/-0.55-1.96/...`）。已改 13。

**④ 我自己写错过一次剪枝条件**（在排查账户日点时的临时探针里）：
`if stored-(a+lo) > 0.01: continue` 会把所有「累加值还低于目标」的分支全剪掉 →
恒返回 0 解。这类剪枝的正确条件是 `a+hi < target` 或 `a+lo > target`。
**当时输出是"0 解"，如果我没核对就信了，会得出"任何价格组合都解释不了"的错误结论。**

## 4. 教训

1. **关掉一个机制前，先确认它的开关真的被读。** 本次先查了 `enabled` 是否生效
   （在 `api/main.py:2338` 正确读取），才敢只改配置；否则就是「假关」——
   配置变了、行为没变，比不改更危险（09-16 文档记过同类：`index` 键只对一处生效）。
2. **"没效果"和"负效果"是两回事，报告要给方向。** 站上方向如果只报"不显著"，
   会漏掉「18/18 为负」这个真正的信息。**显著性检验回答"能不能确定"，
   符号一致性回答"往哪边偏"——两个都要报。**
3. **与既有因子重叠的过滤器必须做控制组。** 否则测的是重复计分。
4. **一个机制被证伪后，要顺手订正引用它的注释/文档。** 否则假数据会活到下一轮决策。
